# MR.2 WU8 — Cross-Surface Verification & MR.2 Closure — Pre-contract

Lifecycle: DRAFT / TRIAL / NOT AUTHORITATIVE
Workplan role: forward MR.2 WU8 closure boundary
Promotion status: NOT PROMOTED
Implementation authorization: NONE
Dependency: WU5–WU7 accepted sufficiently for assembled MR.2 verification

## Purpose

Define the bounded final verification and closure unit for the reconciled MR.2 shared Admin refinement topology.

This file is a planning artifact. It does not close MR.2, does not override repository authority, and does not authorize implementation or documentation promotion by itself.

## Objective

Verify the assembled shared Admin refinement foundation across materially relevant Admin surfaces, confirm that shared primitives are truly single-source and exception-aware, disposition remaining MR.2-specific planning payload, reconcile materially stale current-state documentation, and close MR.2 without expanding into domain-specific refinement.

## Preconditions

WU8 must not claim closure readiness unless:
- WU5 shared-primitive scope and exception model are accepted;
- WU6 shared artifact implementation is accepted;
- WU7 representative adoption/propagation proof is accepted;
- no unresolved shared-foundation defect materially undermines the assembled result;
- remaining domain-specific refinement has an explicit owner/disposition outside MR.2.

## Cross-surface verification scope

WU8 must verify, where materially applicable:
- canonical shared primitive single-source behavior;
- page title / eyebrow / page-header consistency;
- surface/card treatment consistency;
- toolbar/search/filter treatment;
- form/helper treatment;
- button/action placement and sizing;
- modal/dialog action rhythm;
- typography and spacing consistency;
- radius/flat-surface default treatment;
- responsive/mobile behavior;
- accessibility behavior;
- explicit semantic exceptions;
- System Manager shared presentation consistency without taking domain ownership;
- no accidental restoration of retired product-facing managers;
- truthful empty/unsupported states rather than fabricated capability.

## Ownership and architecture checks

WU8 must confirm that MR.2 did not:
- transfer domain behavior into shared presentation artifacts;
- recreate standalone Module Manager ownership;
- recreate standalone Settings Manager product ownership;
- restore Redirect Manager;
- silently decide Taxonomy Manager final disposition without sufficient evidence;
- make Dashboard composition part of MR.2;
- pull future per-Bundled-Module refinement back into MR.2;
- introduce placeholder Security/Email/System capability where authoritative capability does not exist.

System, Site, Security, Email, System Health, and other parent-surface concerns must either be consistent with their accepted owner or be carried forward explicitly with a truthful bounded disposition.

## Old Media WU5 closure-time disposition

WU8 must ensure the historically promoted/rejected Media WU5 attempt is no longer misleading as forward MR.2 scope.

Its remaining delta must be durably classified as appropriate into:
- retained correctness fixes;
- shared-artifact work already absorbed by WU5–WU7;
- future Media Manager refinement;
- rejected/local redesign not carried forward.

WU8 must not use closure as permission to complete Media-specific refinement.

## Thread-level planning disposition

The Shared File Intake Interaction Pattern must receive a durable disposition if it remains material at closure.

Valid outcomes include:
- promote into an individual Concept/source for future work;
- re-home into a specific future owner workstream;
- explicitly defer;
- reject/supersede if no longer valid.

MR.2 should not close while material thread-only planning payload would be lost or would mislead the next planning target.

## Documentation consistency

Before MR.2 closure, perform a focused documentation consistency audit against the accepted assembled state.

Preserve intentional historical records, but correct materially misleading current-state wording, including where applicable:
- roadmap/current-state descriptions;
- active MR.2 contracts and forward-topology wording;
- old Media WU5 forward-scope language;
- Admin UI/shared artifact documentation;
- architecture/manager ownership wording materially affected by MR.2.

Do not rewrite historical contracts merely to make old wording look current. Use explicit historical/superseded disposition where needed.

## Explicit exclusions

WU8 does not authorize:
- full per-Bundled-Module UX refinement;
- Dashboard composition/widget redesign;
- new domain capability;
- schema/persistence changes;
- ownership expansion;
- Deferred Item adoption;
- production reconciliation;
- release/tag/publication/distribution;
- unrelated cleanup outside what is necessary for truthful MR.2 closure.

## Closure acceptance direction

MR.2 may close only when evidence demonstrates that:
1. intended shared primitives are single-source and propagate correctly;
2. accepted exceptions are explicit and bounded;
3. representative and cross-surface behavior remains responsive and accessible;
4. domain semantics and ownership remain unchanged unless separately authorized elsewhere;
5. no retired-manager ownership was accidentally restored;
6. no hidden per-module refinement was smuggled into MR.2;
7. unresolved MR.2-specific planning payload has durable disposition;
8. materially relevant repository documentation is no longer misleading;
9. old Media WU5 forward-scope ambiguity is durably reconciled;
10. remaining domain refinement has explicit future ownership rather than being silently dropped.

## Closure result boundary

WU8 closure establishes only the completion of MR.2 shared Admin refinement scope.

It does not close future Media, Navigation, Theme, Users & Access, Form Manager, Dashboard, or other dedicated workstreams.

## Promotion and authorization boundary

This pre-contract may be revised during review.

Only explicit promotion may create an authoritative WU8 closure contract. Actual MR.2 closure additionally requires accepted implementation/verification evidence, documentation consistency, required repository lifecycle closure, and explicit objective closure recording in authoritative repository state.
